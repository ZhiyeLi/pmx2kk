pmx2KK 0.2.1 — Blender 原生 KK 部件转换插件

完整教程与源码：https://github.com/ZhiyeLi/pmx2kk
自主源码仅限非商业使用，见包内 LICENSE；第三方许可见 THIRD_PARTY_NOTICES.md。

适用：Windows、Blender 4.5 LTS、原版 Koikatsu（Unity 5.6.2）。
这是可运行的首版工具，需确认分件并检查结果，不是任意 PMX 无人值守转换器。
不支持 Koikatsu Sunshine、男性骨架、任意自定义骨架。

安装与依赖
1. Blender 编辑 → 偏好设置 → 插件 → 从磁盘安装，选择 pmx2KK-0.2.1.zip 并启用。
2. 展开插件偏好设置，指定本机 KK、SB3Utility、mmd_tools、Studio 材质模板。
   本次验证：Blender 4.5.0、SB3Utility 24.3.3、本机 mmd_tools。
   mmd_tools 请选择包含 __init__.py 的 mmd_tools 文件夹；自带 OpenCC wheel
   会解压到当前任务的隔离目录，不会通过 pip 修改全局 Python。
   Studio 材质模板需要包含 Shader Forge/main_item_studio 材质。
   模板获取步骤见仓库 docs/SETUP.md；本插件不分发模板资源。
   模板、SB3Utility、游戏资源、人物模型都不包含在插件 ZIP 中。
3. 若希望同时输出人物卡，指定一张本地原版 KK 女性基础卡。
   不指定基础卡时仍可生成 zipmod，在 KK 中选择新头型、前发和上衣并保存卡。
4. KK 端使用已有的 BepInEx / Sideloader / ExtendedSave 环境。
   原色瞳孔人物卡还需要 KK OverlayMods（KSOX，本机已有 6.3）。
   脸部皮肤走原生头型纹理入口；左右虹膜通过卡内 EyeOver 保留颜色与高光。
   单独装 zipmod 不包含卡内彩色眼贴图：请同时使用生成的 native.png 人物卡。
   不需要安装 pmx2KK 运行时插件，也不需要 MCP 或 AI agent 执行转换。

操作
1. 在 3D 视图按 N，打开 pmx2KK 页签。
2. 选中具体 PMX 文件，并选择与源模型分开的工作目录。点击“检查 PMX”。
   每个源 PMX 的内容哈希决定独立任务目录和资源 GUID；同源重建复用 ID。
3. 点击“载入源模型”。逐项检查材质分类，可选中部件定位。
   身体/服装：原衣服、身体皮肤、鞋、手套等随身体变形。
   头发：静态头部跟随，或可选短刘海模板摆动。
   头饰：固定跟随头部。长垂饰的物理需后续专门适配。
   脸部皮肤：当前需要恰好一个面部皮肤材质，作为 KK 原生脸型拟合参考。
   瞳孔：指定原始虹膜材质，支持左右不同颜色。多个眼睛材质按实际表面积
   选择主体，另行合成中性高光；不会把小高光当作眼距测量点。
   其他五官：眉毛、睫毛、口腔和表情结构使用 KK 对应部件；不移植 PMX 特效。
   忽略：不导出的附件、独立道具。
   帽衣分割：同材质混有帽子和衣尾时，按缩放后的源模型 Z 高度拆分。
4. 若提示未映射变形骨骼，在“骨骼覆盖”中填入实际 KK 骨骼名，例如
   cf_j_hand_R。独立道具也可直接在部件列表中忽略。
   普通辅助骨骼会沿父级寻找解剖骨骼；不会把 MMD 元数据组当成蒙皮权重。
5. 默认先按双眼中心、眼距与眼到下巴高度归一化；耳朵、光环、发饰不参与
   头部尺寸估计。脸、头发、头饰及颈部衔接共用同一基准。身体宽度以肩关节
   距离为基准，不再按头部离地高度推算。
   需要时微调身体横向比例、头发比例/位置、脸型拟合强度，勾选确认框。
   头发比例微调绕归一化后的眼部中心缩放，不会随源模型离地高度产生漂移。
   大网格默认拒绝超限导出；可主动启用“允许简化超大网格”。减面仅作用于
   工作副本，需检查轮廓、手指和细节。打包端还会检查最终导出顶点数。
6. 点击“转换并渲染”，再“载入转换预览”。生成正面、侧面、背面 PNG。
   Blender 预览用于几何、贴图、分件检查。KK 的眼睛等运行时材质在 Blender
   中不完整，不能据此判定游戏内表情。实际效果需要在 KK 验证。
7. 点击“生成 zipmod”。当前参数会保存到 recipe.json，可用文件夹按钮恢复。
   任务后台执行，可取消；实时 Blender 场景不会被后台 worker 打开或覆盖。
8. 任务目录/output 中包含 zipmod；指定基础卡后另有 native.png、card.json。
   将 zipmod 复制到 KK/mods，卡复制到 KK/UserData/chara/female 后重启 KK。
   插件自身不会自动部署到游戏目录。

产物与限制
- 输出为原生头型、前发和整套上衣部件。鞋/手套等目前包含在整套上衣里，
  还不是分别独立选择的原生衣橱。整个上衣可替换，原生身体会随之恢复。
- 面部是保留 KK 拓扑、UV 和 81 个表情通道的近似拟合，不是 PMX 脸的无损移植。
  自动转移 PMX 面部皮肤与腮红颜色；使用源 UV 正面采样和连续边界补色，
  不再用固定椭圆色块覆盖眼周、嘴周。眼白、口腔和深色描线不作为皮肤转移。
  强对比面纹/纹身可能被皮肤筛选排除，仍需人工单独适配；不是任意脸纹无损烘焙。
  拟合采用有上限的平滑位移；UV 接缝重合点共享位移，锁定眼睑和唇部并更新法线。
  皮肤使用未压缩 32 位 DDS mip 链进入 Unity，避免默认 DXT5 把浅色渐变量化为色环。
  眉睫形状、眼裂、嘴唇仍属 KK 原生。
  KK 表情同时使用骨骼与 blendshape；保留这些结构，纹理会随表情一起变形。
- 新卡重置脸/身体比例为统一基准，不继承利维坦或其他基础卡的捏脸尺寸。
  仍可在 KK 调整，但大幅调整头型后需重新检查头发、饰品和颈部贴合。
  基础卡未被替换的头发依赖保留；旧插件扩展数据不复制，新增 KSOX 瞳孔数据。
  所有衣装坐标使用新上衣，其余衣服槽清空，基础饰品清空。
  基础卡最好预先使用空的后发/侧发/扩展发。保留的 mod 依赖写入 card.json；
  若使用第三方空发型，仍需安装该发型所属的 mod。
- 新卡最初使用 Blender 几何预览缩略图。加载 KK 后保存可获得游戏内缩略图。
- “固定在头部”是默认值。短刘海模板只作用于前额附近；不等于 PMX 长发、
  裙摆和刚体约束的自动物理转换。长发、裙摆仍需人工专门绑定/验证。
- 身体和头发保留 PMX 贴图与源 UV；原生头型和虹膜重新采样到 KK UV。
  普通肤色/腮红可转移；彩色眼部特效、混合虹膜与眼白的材质需人工分件。
  材质混有多个部位、
  特殊透明效果、复杂附件、肩部/颈部接缝仍需视觉检查。
- 高低模目前复用同一导出网格，不提供单独的 LOD 优化。
- 只读原始 PMX/贴图/游戏资源。中间数据、模板副本、日志在工作目录。
  同一源重新生成会更新该任务产物。已载入预览副本不会自动反向写入转换配方。
- 源 PMX 变化后需重新检查。转换完成和游戏内验收分别记录，打包成功不代表
  每个模型的姿态、表情、接缝、透明材质都已通过验收。
- v0.1 / v0.2.0 配方需要重新“检查 PMX”建立带 n21 后缀的新任务；旧模型和交付不覆盖。
  fit.json 保存实际标记点、归一化尺度和选择的虹膜材质，便于复查。
- 尊重原模型作者的使用条件；生成的游戏资源包和人物卡默认用于本地测试。

开发入口
worker.py <recipe.json> inspect|convert|build，通过 Blender --background --python 调用。
backend/*.ps1 使用独立 PowerShell 进程调用本地 SB3Utility。
card.py 离线构造原版 KK 卡；vendor/msgpack 是 MessagePack 1.2.4 的纯 Python 实现，
许可见 vendor/msgpack/LICENSE。插件中不包含模型、游戏资源和第三方可执行文件。
