# 从 PMX 到原生 KK 人物卡

先完成[环境搭建](SETUP.md)。本教程面向原版 KK 女性人物。转换始终使用原模型的穿着外观进行几何与动作检查；模型来源及规约见本文末尾。

## 1. 检查源模型

在 Blender 4.5.0 的 3D 视图按 `N` → pmx2KK。选具体 `.pmx` 文件，设独立工作目录，保持导入比例 `0.08`，点击 **检查 PMX**。等待任务结束后 **载入源模型**，查看正、侧、背面及贴图是否齐全。

部件来自 PMX 材质分组。自动判断只提供初始分类，需要人工确认。三个已验证模型可用[示例 preset](../examples/README.md)，并核对 SHA256 与材质名称；其他版本不要强行套用。

## 2. 分类与骨骼

| 分类 | 用途与注意事项 |
|---|---|
| 身体 / 服装 `BODY` | 随身体骨骼变形；源身体皮肤、衣服、鞋、手套等合为一个上衣部件 |
| 头发 `HAIR` | 跟随头部；默认静态，可选短刘海物理 |
| 头饰 `HEAD_ACCESSORY` | 固定跟随头部；不是按手、胸或腰骨骼运动的配饰 |
| 脸部皮肤 `FACE` | **必须恰好一个**，用于脸型和皮肤采样，不直接把 PMX 脸 mesh 放进 KK |
| 瞳孔 `IRIS` | 原虹膜材质；转移颜色及高光，左右分别采样 |
| 其他五官 `FACE_DETAIL` | KK 原生眉、眼线、嘴和口腔；不会直接移植 PMX 特效。已有示例中部分虹膜沿用此分类，由转换器的虹膜识别规则选出 |
| 忽略 `IGNORE` | 独立道具、特殊表情面片或不需导出的部件 |
| 帽衣分割 `SPLIT_HOOD` | 同一材质同时有帽子与衣尾时，按源模型缩放后世界 Z 高度拆分 |
| 待确认 `AUTO` | 需要检查后明确分类 |

点部件选择按钮在场景中定位。眼白与虹膜混在同一材质、多个脸材质、复杂透明特效可能需要先在工作副本中手工拆分，修改源文件后重新检查。不要把整个眼睛周边或高光片单独误当主要虹膜。

标准 MMD 日/英文骨骼会自动映射；辅助骨骼沿父级寻找可用解剖骨骼。出现无法映射的有效变形权重时，在“骨骼覆盖”填入正确 KK 骨名，例如 `cf_j_hand_R`。不要为了通过检查将所有未识别骨骼随意指向头部。独立道具可以忽略；非标准骨架需要人工修复。

## 3. 比例、脸型和物理

| 参数 | 默认值 | 何时调整 |
|---|---|---|
| PMX 导入比例 | 0.08 | 模型单位异常；改变后必须重新检查 PMX |
| 身体横向比例 | 1.0 | 自动肩关节宽度适配后的细调 |
| 脸型拟合强度 | 1.0 | 0 更接近原生 KK；1 为有上限的源脸拟合；异常时逐步降低 |
| 头发比例微调 | 1.0 | 头发/头饰与脸贴合；绕归一化眼部中心缩放 |
| 头发偏移 | 0, 0, 0 | 缩放后仍存在整体位置偏差 |
| 帽衣分割高度 | 1.0 | 仅作用于 `SPLIT_HOOD`；使用导入比例后的源世界 Z 高度 |
| 头发物理 | 固定在头部 | 初次验收先静态；短刘海模板仅影响头部附近前侧发梢 |
| 阻尼 / 刚度 / 弹性 / 惯性 | 0.55 / 0.85 / 0.35 / 0.8 | 短刘海模板动态参数，需要游戏内运动检查 |
| 描边宽度 | 0 | 按实际材质效果小幅调整 |
| 允许简化超大网格 | 关闭 | 超过原版单 mesh 导出顶点预算时可选；减面后重新检查细节与权重 |

系统按双眼中心、眼距、眼到下巴距离建立共享头部基准，耳朵、光环和发饰不参与头部尺寸估计。肩关节距离用于身体宽度。不要靠全身最高点或头饰高度手工归一化。

脸的拓扑和 UV 仍来自 KK；皮肤按源 UV 重新采样，嘴眼附近连续补色。强对比面纹/纹身可能被皮肤筛选过滤。眉形、眼裂、嘴唇属于 KK 原生结构，无法保证 PMX 的所有细节一模一样。

## 4. 转换、预览、打包

勾选 **我已检查部件分类与骨骼映射**，点 **转换并渲染**。后台生成正/侧/背面 PNG；结束后点 **载入转换预览**。检查：脸与头发比例、耳饰位置、肩颈衔接、手脚姿态、鞋尖、衣服轮廓和透明处。

Blender 预览主要检查几何和原贴图，无法完整模拟 KK 眼睛和实时材质。预览副本上的手工移动不会自动写回 recipe；需要调整面板参数后重新转换，或在独立工作副本中开发适配。

确认几何后点 **生成 zipmod**。参数保存到任务 `recipe.json`，右侧文件夹图标可恢复该配置。后台任务可取消；失败时检查日志，不要连续启动重复任务。生成包不会自动复制到游戏。

任务目录示意：

```text
工作目录/
  _templates/             本机 KK 提取缓存，不能发布
  p<源文件哈希前12位>n21/
    recipe.json           机器路径 + 分类 + 参数
    inspect.json          部件和骨骼检查结果
    source.blend          原始导入的工作副本
    converted.blend       转换预览副本
    fit.json              归一化、拟合、虹膜选择等诊断
    status.json           后台阶段与状态
    output/
      <key>-native.zipmod
      <key>-native.png    指定基础卡时生成
      card.json           卡数据与保留依赖
```

同一源文件内容重建会复用 GUID 和 ID，更新同任务产物。要保留某次结果请先备份。v0.1 / v0.2.0 应使用 0.2.1 重新“检查 PMX”建立 `n21` 任务，不能直接改旧 recipe 的版本号冒充迁移。

## 5. 安装到 KK 与验收

1. 关闭 KK，将 `*-native.zipmod` 复制到 `KK/mods/`，把 `*-native.png` 复制到 `KK/UserData/chara/female/`。避免同一 GUID 的旧包和新包同时存在。
2. 启动 KK，确认 BepInEx、Sideloader、ExtendedSave 和 KK OverlayMods 正常加载。载入新卡。
3. 保持原穿着，检查脸部特写：正面/侧面皮肤、眼周/嘴周、腮部、瞳孔颜色、高光和透明边缘。
4. 测试眨眼、张嘴、表情和小幅脸型滑块，检查发饰与脸的贴合。
5. 在 Studio 测试站立、抬手、行走等姿势，检查肩、肘、膝、脚尖及衣服穿模；开启短刘海物理时额外检查转头与运动。
6. 替换整套上衣，确认原生身体恢复；切回生成上衣。当前鞋/手套/衣服不是分别独立的衣橱项目。
7. 保存新卡，再载入，确认头型、衣服、瞳孔颜色和依赖仍正确。初始卡使用 Blender 缩略图，在 KK 保存后才获得游戏内缩略图。

只装 zipmod 可以手工选择原生部件，但卡内彩色虹膜 Overlay 数据不会由 zipmod 单独提供。要复现验收效果，请配套使用生成卡。未指定基础卡时，需要自行创建并配置人物卡和眼贴图。

转换完成不等于任意 PMX 都通过游戏验收。三个示例的最后一轮重建耗时约 38–65 秒，但这不包含首次模板提取、人工调整与游戏启动；详见[验证记录](VALIDATION.md)。
